## 1. C9-1 (G9-6, High): outbound TLS hostname verification has a test per client

### What was added

`apps/api/test/tls-verification.test.ts`, a new block `G9-6: every outbound TLS client refuses a certificate for
another name` (6 tests). A CA is minted at test time with the `openssl` CLI (the key never leaves a temp
directory; nothing committed), added to the process default trust store with `tls.setDefaultCACertificates`
(restored in `afterAll`; the repo pins Node 26), and signs two leaves:

- a **right-name** leaf valid for `localhost`, `ntfy.c9.test`, `llm.c9.test`, `mail.c9.test`, `127.0.0.1`;
- a **wrong-name** leaf valid for `evil.test` only. The chain is valid; only the name is wrong.

Each shipped client (the real `createNodeTransport()`, `createLocalEndpointTransport()`, `createPlaidApi()`,
`fetchTransport()`, `createSmtpChannel()` with the real nodemailer) is driven twice with identical dial parameters
and only the port different: against the right-name server it completes (positive control, so a refusal is about the
name and nothing else); against the wrong-name server it must fail with a hostname error
(`ERR_TLS_CERT_ALTNAME_INVALID` / "does not match certificate's altnames"), and the wrong-name server must have seen
**no request, no body, no application byte** (a counter on every `secureConnection` socket's `data`, so a Plaid
secret or bearer token written to the wire is caught even if the HTTP layer never parses it). A completed TLS
handshake alone is not a leak and is not asserted against (Node checks the name after the handshake and before
writing).

Tests (all in `api` project):

1. `G9-6 … the positive control: a client that trusts only the CA completes a request to each server by its own name`
2. `… the shared egress transport (ntfy, market data, Esplora): works by the leaf's name, refuses another name and writes nothing`
3. `… the local-endpoint transport (a remote https model): works by the leaf's name, refuses another name and writes nothing`
4. `… the Plaid client (axios, as createPlaidApi builds it): works by the leaf's name, refuses another name and sends no secret`
5. `… the Coinbase transport (fetch): works by the leaf's name, refuses another name and sends no bearer token`
6. `… the SMTP adapter (nodemailer, implicit TLS): reaches the greeting by the leaf's name, refuses another name and sends no EHLO or password`

Green on HEAD: `Tests 14 passed (14)` (8 existing + 6 new).
