## 5. Keyboard (`e2e/a11y-keyboard.spec.ts`, `support/keyboard.ts`, `support/virtual-passkey.ts`)

The spec and its helpers never touch the pointer; a structural test reads the files and fails on `mouse`, `click()`, `dblclick`, `tap`, `hover`, `dragTo`,
`check`/`uncheck`/`setChecked`, `selectOption`, `dispatchEvent`, `fill` and `focus()` (§7). Navigation to a screen is `page.goto`; everything after is `page.keyboard`.
`Journey.check` runs at every stop:

- **2.4.7**: the focused element draws an outline or ring (a combobox's highlighted option counts; a native date field's browser-drawn part is accepted).
- **2.4.11**: it is in the viewport, and `elementFromPoint` at its centre and four inset points (over the part that is on screen) returns the element or its
  own content, not the bottom tab bar, a toast or a scrim. (Stricter than the AA text, which only forbids "entirely hidden".)
- **2.4.3**: `assertReadingOrder` over a Tab walk (within a region, a stop may not lie wholly above the previous one; regions are not revisited), and
  focus-returns-to-the-trigger in every journey and in the sweep.

## 10. Decisions, wiring for the orchestrator, open items

### Decisions

1. **`@theme inline` for the colour mappings** (§4.1). Utilities read `var(--bg-page)` directly, so a `data-theme` on anything but `<html>` repaints them. It changes the CSS Tailwind emits for every colour utility; the real app only ever sets the theme on `<html>`, so the output there is equivalent (the whole suite is green on it).
2. **Reduced motion is exactly 0 s**, not `0.01 ms`, because the exit test says "nothing animates" and the checker reads the computed value. Base UI's exit animations wait on `getAnimations()`, empty at 0 s; every dialog, sheet and popover in the suite still opens and closes.
3. **The measured second opinion on axe's `incomplete` colour nodes is part of `runAxe`.** A node it cannot decide is measured from computed colours over the ancestors' backgrounds; a gradient/image/translucent background is reported as unresolved (it was 0). This is what makes a green axe mean "measured", and S5 shows it seeing what axe alone calls "incomplete".
4. **The sessions screen (`GET/DELETE /auth/sessions`, `DELETE /auth/totp`) is not built here.** Cheap in code, but it needs its own step-up journey, mocks and a decision on where it lives in Settings; it is recorded for 9.14 (wp9.11 §5). The generated client has the calls (`pnpm run gen` was run; no diff).
5. **Dismissing a Brief item and Accept now use `aria-disabled`** while the request is in flight instead of `disabled` (a disabled button drops focus). The mutation guard moved into the click handlers.
6. **Chart tables are disclosures, closed by default**, so no screen changes until asked. The fan chart's own "View as table" (WP 4.10) was left alone.
7. **`playwright.config.ts`'s two `testMatch` entries (`a11y-sweep`, `a11y-keyboard`) were already in the tree** from the first agent's snapshot; this finisher did not change the file.
8. **The sweep's results go to `$TMPDIR/personalfi-a11y-sweep/`**, not `test-results/` (Playwright empties that on every run, which would defeat resuming by route). Screenshots default to a gitignored directory; the committed `wp9.8-*.png` were written once with `PLAYWRIGHT_EVIDENCE_DIR=docs/evidence/phase-9`.

### Wiring for the orchestrator

- **O-6, API half:** `apps/api/src/routes/domain-errors.ts`, `connectorDetail`. Reconnect the connection to continue." The web now shows its own words for that code (so nothing user-visible depends on this), but the API's detail is wrong for a link-time refusal; the one-line fix is a branch on the kind. - **RUNBOOK / release notes:** nothing required. If a line is wanted for v0.9.0's notes: "Every screen now has its own page title; every chart has a data table; the soft-lock traps focus; Escape closes dialogs from a category field."
