## 4. Decisions

1. **Where the app places figures: in the validator, after checking the narration as written.** The narration is judged in slot form, where a digit the app did not place can still be told apart. It is then filled, and the unchanged 1.5.0 narrow trace runs on the filled text, against the finding filled the same way. Step 7's rule is not widened: what the holder reads passes the old rule and a strictly narrower new one. `ValidatedInsight.insight` is the filled copy, so no stored narration carries a slot.
2. **A placed figure is written `value (label)`.** The figure-half of R-2 asks that the app bind each slot to its label. Citing the row under that label is a binding the evidence panel shows; putting the label beside the figure is the binding the reader sees in the sentence itself, so a swapped "from … to …" reads as what it is (O-45). This costs some fluency; the wording is "AI-assisted" and never replaces the built-in's.
3. **What "a digit the app did not place" admits:** a slot's fill, and text the model was shown and copies verbatim — a clause of the slotted prose, a date or pseudonym token in it, an evidence label. Never a free figure: the figure set a placed narration may write is empty, in digits and in words. A derived rendering the finding prints without a row (`7.0pp`, `$632.98`) may only be quoted inside its own clause, which is no wider than under option A.
4. **The model writes no evidence and no identity.** The B grammar drops `evidence` and requires `finding` (enum 1–5). The narrator writes the identity from the number (A(a)'s numbered path) and each placed slot's citation from the row. A narration that places no slot cites its finding's first row with `value: null`.
5. **The impact display is a figure row** (`Per year`, `One time`, no ref) unless a row already states it, so "about $36.00 more a year" is a slot like any other. It has no ref to cite; its label sits beside it in the text.
6. **The cold-model design (C5-2):** set out in §0, measured in §2c. The alternatives were rejected for these reasons. Spreading the enqueue would not help, because only the first item was cold. Raising the chat timeout would let every warm narration run longer before the breaker counts it.
7. **Approvals written before B cover a different query shape.** The prompt template (`/2`, new rules and the warm-up constant) and the reply format changed, so the adapter's template hash changed (`47aa506e…` → `cdfc1679…`). WP 5.1's query shape includes that hash, so an install must approve the narrator's payload preview again (RUNBOOK "Local model" step 6). This is the intended behaviour: the holder approved bytes that are no longer the ones sent.
8. **The 1.5.0 envelope is kept, not deleted** (`narratedFindingOf(source, 'quoted')`). The WP 5.3/5.3b/A tests pin the narrow trace on it, and that trace still runs, on the filled text, for every placed narration. No production path builds it.
