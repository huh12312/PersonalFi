## 3. Decisions

### 3.1 The R-2 gate: narration text is withheld until the gate says otherwise

Phase 5 gate R-2: the figure half of the slot-reference escalation (WP 9.5 option B) is mandatory before any narration text reaches the holder, unless Chris accepts the residual in writing. So item 3 ships in two layers.

- **Always on the wire:** `narration.status` (`narrated` | `pending` | `none`), `narration.aiAssisted` (true exactly when narrated), `narration.textShown`. The badge costs nothing in R-2 terms: it carries no model-written word.
- **Only when `NARRATION_TEXT_SHOWN=true`:** `narration.summaryMd`. With the key off (the default) the route returns `summaryMd: null` and the web shows the built-in's own wording plus "An AI-assisted wording of this item exists and is not shown yet." The gate is enforced in the route (S20), not the screen; the screen additionally refuses to render text it was not sent (S30).
- **"pending"** is a promise only while something keeps it: a narration is expected only when a model is configured (`localModelPin`) and the Brief is inside a window after publication (S24, S25). Otherwise "none".
- **Who flips it.** Nothing in the app does. The orchestrator sets `NARRATION_TEXT_SHOWN=true` when 9.5 reports option B landed **and** measured >= 95 %, or when Chris accepts the R-2 residual in writing. **At the time of this evidence the gate stays closed:** option A measured 91.1 % (steps 1-5) and 85.7 % (steps 1-7), below the bar, and B is in flight in another package. Nothing here pins a prompt-hash literal; approvals written before B are a different query shape afterwards and the tests build the approval through the real preview route each time.

### 3.2 The config shape

Two new keys, `LOCAL_MODEL_PIN_NAME` and `LOCAL_MODEL_PIN_DIGEST`, both-or-neither (a half is a boot error: `resolveLocalModelPin`, S2), and `NARRATION_TEXT_SHOWN` (`z.stringbool().default(false)`, S1). The api learns the model's name and digest and never its endpoint. A process holding the full `LOCAL_MODEL_*` set (the worker) pins from that and ignores the PIN keys. The kind GET's `configured` is therefore "the api has a pin" (or the full set), not "the worker can reach the model": compose defaults the api's pin from `LOCAL_MODEL_NAME`/`LOCAL_MODEL_DIGEST` (Wiring below) so the operator sets the model once. If they ever diverge the screen says what the api knows; the preview refuses with a named 503 rather than approving a hash the worker would not compute.

### 3.3 Why the executor is never bound on the api

Approval is keyed to the template hash, so the api needs the renderer and the manifest; it needs nothing that can run or dial. `createPreviewModel` returns a frozen manifest with a `run` that rejects, and the adapter underneath is built over a transport that rejects, with no endpoint policy at all, so even a code path that reached `run` would refuse rather than connect (S9, test `…holds a manifest and a renderer and nothing that can run or dial`). A compromised api therefore gains nothing it could dial.

### 3.4 `createPreviewModel` delegates to `createNarratorWiring` (S4')

Yes. After 9.5's relay the api's renderer is built through `createNarratorWiring`, the constructor the worker's own adapter comes from, so the prompt, the reply format and the sampling options that feed the template hash are one definition. Drift is structural: no `generation` or `format` parameter exists to pass. The CF-1 test builds the worker side through the same function and would turn red on a drifted template hash (it did, at S4, before the relay).

### 3.5 G5-3: refuse or flag

For a `local_model` or `external` advisor a **newly granted** scope its manifest does not request is refused 422 `insights.scope_not_requested` and nothing is written: its data crosses a boundary to something that never asked. A **builtin** is in-process and `effectiveRunScopes` intersects with `requires_scopes` anyway, so the grant is allowed and flagged (`notRequested` in the answer, a line on the screen). A standing grant that predates the check can still be left alone or revoked; revoking is never refused. On screen a refused box is disabled and says why; a granted-but-unrequested scope stays revocable (S41, S42).

### 3.6 The feed's empty state (item 6)

Consent is the reason only when every enabled, un-quarantined advisor holds no grant. The screen derives that from `GET /advisors` (no new route). It deliberately says nothing when the list cannot be read (a failed read must not become a claim) and when only some advisors lack access it keeps "all caught up" and counts them, because a feed produced by the advisors that do have access is a genuinely empty one.

### 3.7 CF-24 and O-9 storage
