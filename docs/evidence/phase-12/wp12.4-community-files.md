## 3. Choices made

- **Licence line, not a CLA and not a DCO.** CONTRIBUTING says "By opening a pull request you agree that your contribution is licensed under the repository's MIT licence" and states there is no sign-off line. A sign-off needs tooling to enforce and adds friction for a one-maintainer project; the MIT licence on the repository is the grant, and the sentence records the intent.
- **Acknowledgement window: 7 days.** No SLA on fixes; a fix is a normal signed release. Change the number in `SECURITY.md` ("What to expect") if you prefer another.
- **No email address anywhere.** Reports go through GitHub private vulnerability reporting. The path stated is Security tab, Advisories, Report a vulnerability.
- **Certificate identity regexp** is 06 §5.3's with this repository's path and a stricter tail: `^https://github.com/huh12312/PersonalFi/\.github/workflows/release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+$`. It matches what `scripts/verify-release.sh` builds (`refs/tags/v<release>`). Image tags carry no leading `v`; the examples use `0.10.0`.
- **Hub namespace `masterhuh`** (settled after dispatch, per the coordinator) is written out in the README support matrix, `SECURITY.md` and the Hub page; no placeholder remains.
- **README "Install" is still build-first.** The new section says so and points at the RUNBOOK's Upgrade section for the verified-pull path, so it does not claim WP 12.3's pull-first quickstart exists.
- **Scope items beyond the brief** in `SECURITY.md` (a signed-in user's denial of service against their own install, scanner output with no demonstrated effect, configurations the documentation forbids) are mine; strike any you do not want.
- **The Hub page quotes the first three sentences of the README's first paragraph**; its fourth (the egress sentence) is left out to keep to three.
