# WP 12.6: Yahoo Finance through yfinance, opt-in

**Request.** `docs/research/14-yahoo-finance-optional.md` (D33). Every row of its §3 table is a requirement, and §2 is the posture: unofficial, never the default, the holder opts in, and every figure is labelled. Chris, 2026-11-02: "I want to enable the yahoo finance python as an optional component for users. I realize it has licensing risk, hence why we will make it opt in."

**Result.**

1. **A fourth image, `personalfi-yahoo`.**
   - Base: `python:3.15.2-alpine3.24`, pinned by its multi-arch index digest.
   - `yfinance` 1.7.0 and its 22 dependencies, each pinned by version and sha256, installed with `--require-hashes --no-deps --only-binary=:all:`.
   - A build-time check: the version that imports must equal the pin. pip is removed after the install.
   - Runs as uid 10004 on a read-only root filesystem with no shell at runtime.
   - Scans clean: 0 HIGH/CRITICAL, with or without `--ignore-unfixed`.
   - Builds for amd64 and arm64.
2. **A sidecar, `docker/yahoo/server.py`.** It uses only the standard library and yfinance.
   - Endpoints: `GET /health`, `/quote`, `/fx` and `/search`, all JSON.
   - A **host check runs before every outbound request and every redirect hop**. It allows exactly `query1.finance.yahoo.com` and `query2.finance.yahoo.com` on port 443.
   - A budget of 60 requests per sliding hour, and exponential backoff after a 429.
   - A 15-second timeout on each request; no proxy, no custom DNS, and the environment is not trusted.
3. **Compose.**
   - Service `yahoo` runs under `profiles: ['yahoo']` on network `yahoo`. That network is not internal, and its only members are `yahoo` and `worker`.
   - It has the `x-common` hardening, CPU, memory and pids limits, and a healthcheck. It has no secret and no environment from `.env`.
   - `YAHOO_FINANCE_ENABLED` is passed to both `worker` and `api`.
   - Eight `yahoo-*` hardening rules were added, each seen red in the self-test first.
4. **The adapter, `@ctx/integrations` `adapters/yfinance.ts`.**
   - It speaks to `http://yahoo:8000` through `@core/platform`'s local-endpoint transport: one host, one port, private addresses only, no redirects.
   - It asks **both halves before every request**.
   - It enforces `YFINANCE_WINDOWS` and backs off on 429.
   - Every failure is an outcome in the existing vocabulary, never a throw.
   - Every quote carries the label "Yahoo Finance via yfinance — unofficial, best effort".
5. **No direct egress to Yahoo.** `policyFor('yfinance')` and `baseUrlFor('yfinance')` now throw. `MARKET_DATA_ALLOWED_HOSTS` is unchanged, and a test proves it.
6. **The holder half.**
   - Migration `0064_market_data_consent.sql` (expand-only, new table) stores the versioned consent `yahoo-consent/1` with its sha256 and time.
   - `PUT` and `DELETE /market-data/providers/yfinance/consent` both need a step-up.
   - `PUT /market-data/priority` refuses `yfinance` without a current consent (409).
   - Unticking removes Yahoo from every ladder in the same transaction.
7. **The refresh uses Yahoo only where the holder ranked it** (`providersForKind`).
8. **Release and CI.** The fourth image was added to:
   - ci.yml's scan matrix;
   - release.yml's publish matrix (both registries, signing, attestation), its verify loop and its Hub description;
   - `release-workflow.test.ts` (seen red first);
   - `image-names.test.ts`;
   - `build-name-guard.sh`'s self-test.

   `verify-release.sh --with-yahoo` verifies it, and `just upgrade` / `just install-release` pass that flag exactly when the profile is on.

9. **Licences.** The Python tree is gated (`scripts/python-licenses.ts` with `docker/yahoo/licenses.json`) and listed in THIRD_PARTY.md under "Python (the yahoo sidecar)". A GPL entry turns the gate red (tested).
10. **Docs.**
    - RUNBOOK: "Yahoo Finance (profile `yahoo`, opt-in, unofficial)", plus a pointer from Market data.
    - README "What is supported": one line.
    - SECURITY.md: names Yahoo.
    - Release notes: an entry under `## v0.10.2 (in preparation)`.
    - research 14 §5 points here.
    - `.env.example`.

The choices, with reasons:

- **Python 3.15.2**, the newest stable release (2026-10-26). Every compiled dependency already publishes `cp315` musllinux wheels for both architectures, so nothing is built from source, and the image scanned clean on the first try. Nothing else was tried; 3.14-alpine was pulled only for comparison and not built.
- **A new consent table, not the narrator's.** `narrator_provider_consents` belongs to `@ctx/insights`, and its provider CHECK names the hosted language models. Reusing it would put a market-data consent in another context's table and widen a CHECK an existing release relies on. `market_data_consents` sits beside `market_data_runs` in the same shape: version, sha256, given, withdrawn, never deleted. "Add a column to the market-data settings table" was not an option: no such table exists.
- **The outcome vocabulary is unchanged.** `skipped_provider_unavailable` does not exist, so I used the nearest existing outcome in each case:
  - A Yahoo 429 is `rate_limited` with the reason and `retryAfterMs`.
  - A shape change is `error` ("Yahoo's response shape changed (yfinance could not read it): …"), recorded as `failed`.
  - A missing half (a race only) is `refused` with code `yfinance_not_enabled` or `yfinance_consent_missing`.
  - A foreign redirect the sidecar refused is `refused` with code `upstream_host_refused`.
  - No migration was needed for any of these.
- **The api never reaches the sidecar.** The `yahoo` network is `yahoo` + `worker` only, so:
  - `POST /market-data/test-fetch` with `yfinance` answers 400 `market_data.not_testable_here`.
  - The card shows the worker's last recorded outcome and the budget, hydrated from `market_data_runs`.
  - "Refresh prices" runs in the api, so it does not ask Yahoo. Yahoo prices arrive with the 03:45 refresh in the worker. This is a consequence of research 14's network rule; Chris may want a "refresh via the worker" later.
- **Ranking.** `providersForKind` always asks the kind's default provider (as before). It asks `yfinance` only if the holder placed it in that kind's ladder, in the order they placed it:
  - Placed after Tiingo, Yahoo answers only what Tiingo could not (not registered, no key, no data).
  - A Tiingo `error`, `rate_limited` or `refused` ends the walk, so an outage never turns into a burst of Yahoo requests.
- **FX.** The adapter answers `/fx`, but the refresh still stores FX from FRED only. `fx_rates`' CHECK names no `yfinance`, and D17 makes FRED the FX source.
- **`MARKET_DATA_ALLOWED_HOSTS` narrowing does not apply to yfinance.** Yahoo's switch is `YAHOO_FINANCE_ENABLED`, and narrowing only ever names hosts this process may dial.
- **Release verification of the fourth image is opt-in:**
  - `verify-release.sh` checks it only with `--with-yahoo`.
  - `just upgrade` / `just install-release` pass that flag exactly when compose's model contains the `yahoo` service (profile on), and refuse it under any other name.
  - An install without the profile is never refused for, and never pulls, an image it does not run.
- **The two budgets.** The worker counts calls to the sidecar. The sidecar counts requests that actually leave for Yahoo; the first quote for a symbol costs two (the exchange's time zone, then the closes).
- **`settingsAttributions` excludes yfinance.** The label is on the Yahoo card instead, so the screen-wide obligations never put an unofficial source in front of a holder who has not chosen it.
- **frozendict** (LGPL-3.0, named by research 14 §2) is **no longer in yfinance's closure** as of 1.7.0, which ships its own fallback. The record keeps the review reason in case it returns. **certifi (MPL-2.0)** is the one allowed-with-review package.
- **Bundled native code.** numpy's and pandas's wheels bundle the GCC runtime (`GPL-3.0-or-later WITH GCC-exception-3.1`, dynamically linked), and numpy also bundles OpenBLAS. THIRD_PARTY.md records this, but the gate does not check it, because the gate reads each package's declared licence. Chris should know.
- **Found in the first real run:** `COPY --chmod=644` into a directory it creates gave `/app` mode 0644, so uid 10004 could not open `server.py`. The unit tests mount the source and did not catch it. Fixed: `install -d -m 0755 /app`, plus a build-time `su nobody -c 'test -x /app && test -r …'`.

## 2. The pins and how the hashes were made

3. `pip hash -a sha256` runs on every file. Compiled packages get two hashes (x86_64 and aarch64); pure-Python packages get one universal wheel.

### 3.4 The two-half gate

A request reaches the sidecar only if all of these hold, in this order:

1. **The worker builds the view.** `createMarketDataRuntime` adds the yfinance source to a holder's view only when `YAHOO_FINANCE_ENABLED=true`, the process has a sidecar transport (the worker only), and that holder's consent is current. Tests: `market-data-runtime.test.ts` → "not enabled: no source for anyone, and one log line saying so" and "enabled in the worker: registered for a consenting holder only, and one log line".
2. **The adapter checks again, per request.** Before **each** request the adapter checks the operator half and then reads the consent again. A missing half returns `refused` and the transport sees nothing. Tests, all in `integrations/test/yfinance.test.ts`:
   - "a request never leaves with the operator half missing" (the consent is not even read);
   - "a request never leaves with the holder consent missing";
   - "a consent read that fails is not a consent";
   - "the consent is asked before every request, so withdrawing it stops the next one".
3. **Placing Yahoo in a ladder needs the consent.** `PUT /market-data/priority` refuses `yfinance` without it, and withdrawing the consent removes Yahoo from every ladder in the same transaction. Tests: `apps/api/test/db/yahoo-finance-routes.test.ts`.

Log lines, one either way:

- `yfinance not enabled; adapter not registered`
- `yfinance enabled; adapter registered over the yahoo sidecar (each holder must also consent)`
- (api) `yfinance enabled; no sidecar route from this process (the worker registers the adapter)`

### 3.5 No path from the api or worker to Yahoo

- `MARKET_DATA_ALLOWED_HOSTS` still holds exactly the four hosts it held before.
- The context policy refuses `query1`/`query2.finance.yahoo.com`, `fc.yahoo.com` and `finance.yahoo.com` with `host_not_allowed`, before resolving anything.
- `policyFor`/`baseUrlFor('yfinance')` throw `NoDirectEgressError`.
- The adapter's endpoint is `http://yahoo:8000`, and the local-endpoint guard refuses it if `yahoo` resolves to a public address.

### 3.6 The sidecar's host check

Tested in Python:

- Fourteen foreign destinations are refused before anything is sent. They include `fc.yahoo.com`, `guce.yahoo.com`, `consent.yahoo.com`, `http://`, port 8443, userinfo, `169.254.169.254`, `db:5432` and look-alike hosts.
- **A 302 to `https://evil.example/steal` is refused, not followed.** The first hop left and the second never did.
- A 302 to `consent.yahoo.com` on the chart endpoint gives a 502 `host_refused`.
- curl is never allowed to follow redirects itself (`allow_redirects=False` on every call); the sidecar applies the same check to each Location.
- The refusal is a `PermissionError`, so yfinance treats the cookie step as transient and continues without it.
