# WP 11.5d: Ask PersonalFi, advisor mode (the six-step protocol)

**Request (Chris, verbatim).** 2026-10-25: "Good with the llm proposal but I want to expand askpersonalfi to cover being a financial advisor so come up with an expansion proposal there without requiring a fine tuned model." 2026-10-26: "Good with proposal." and, for D31: "Use a hosted model, I agree a locally hosted low parameter won't be strong enough." WP 11.5d is row 11.5d of `docs/research/12-ask-personalfi-advisor-expansion.md` §6, built to §2.3 ("Protocol"), §4 (guardrails), §5 (evaluation), §7 decisions 3–4 and D31.

**Result.**

1. **The protocol as six query types**, each with its own manifest, payload preview and approval in Advisor management, the kill ladder (levels 1–4), one `advisor_runs` row per call with the payload retained for the run inspector: `advisor.clarify`, `advisor.gather` (11.5c's `ask.compile` request, validator and adapter, reused unchanged over the restatement and the holder's answers), `advisor.options`, `advisor.tradeoffs`, `advisor.plan`, and the rubric judge `advisor.judge`. Step 6, `advisor.follow_up`, has no model: a builtin watcher.
2. **Every step validated, by named class** (§1.3): a restatement held to the question's own figures and a goal ref to the refs sent; two to four options, an unbacked one dropped before anything is shown and fewer than two refused (`options.unbacked`); **an option without a cost refuses the step (`tradeoffs.cost_missing`)**; a plan step only ever a link to one of a closed list of real in-app routes (`plan.href_unlisted`, `plan.external_url`, `plan.execution`); every model sentence through the numerals check against the context object, the citation resolver (`resolveCitations`) and the copy linter.
3. **The context object and its digest** (07 §7.3): the clarified question, the answers, the catalogue results (each figure carrying an app-made ref `r<n>:<path>`) and the knowledge sent. Its digest is stored on the session; each later step's payload carries it and is digested by `advisor_runs`. The session row is enough to rebuild it, and a rebuild that does not match the stored digest fails the session (`context_changed`).
4. **Persistence**: migration `0061_advisor_sessions` (expand-only) — `advisor_sessions` (the eleven-state machine, §1.4), `advisor_session_steps` (one row per model call, **UNIQUE (session, step)**: the claim _is_ the row), `advisor_settings` (the consent).
5. **D31: the advisor's own hosted consent**, a tick-box separate from the narrator's (the `categorize.suggest` pattern): `advisor-consent/1`, its sha256 stored when ticked and folded into all six approvable shapes. Unticked (no row) the local model runs the protocol, whatever the narrator is; ticked, the provider chosen for the advisor (default: the narrator's), under that provider's standing consent, key and hourly window. The UI says which.
6. **The rubric judge** (12 §5, decision 3): a rubric per playbook page in code (cost surfaced, non-applicability mentioned, scope kept), scored by a second call that sees **only the narration with every figure, number word and pseudonym masked, and the rubric**. Stored on the session as `judge_score` with its run id; a reply carrying holder-looking data is refused (`judge.holder_data`) and stored as `judge_error`; never a gate.
7. **Follow-up**: the picked plan's figure (a goal's pace, a debt plan's balances, the year's contribution room) is watched by `insights.advisor_follow_up` (daily, 05:40 local, and once at tracking). It writes a `builtin` insight of `advisor.follow_up` with **fixed-template wording**, through the seven-step validator against a builtin snapshot of its one scope — so the **Brief's own job publishes it as an item** (proved: §2, the api-db journey), and a dismissal moves its cooldown ladder like any other's.
8. **Budget and window**: a per-session token budget (60 000; counted from the runtime's own token counts, estimated from bytes when none is reported) stops a session before its next call (`token_budget_exhausted`); a hosted call spends the narrator's hourly window, and the session records what it left. Both shown on the screen.
9. **The api never calls a model.** `/advisor/sessions` writes the session and enqueues `insights.advisor_step`; the worker runs the steps. The session inspector is `GET /advisor/sessions/{id}`.
10. **The sixteenth control check, `advisor_cost_pairing`** (the api's half, no model).
11. **`--advisor` in `scripts/advisor-eval.ts`**: a 27-session golden set (12 §3's three worked examples among them), replayed and run through the shipped adapters over the Ollama fake; the judge's scores reported.
12. **Red team** `apps/api/test/redteam-advisor.test.ts`: the eight probes the dispatch names.
13. **Web** `/advisor` (Overview, after Ask; the mobile More sheet) and the consent card in Advisor management (by a Sonnet-tier sub-agent; §1.6).
14. **Docs**: RUNBOOK "The advisor (v0.9.24)", release notes `## v0.9.24`, 12 §6 row 11.5d, `OWNERSHIP.md`, the migrate test, the soak-canary classification, the export registry.

**No live model was called.** Every model in this package's tests is the Ollama fake, the hosted vendor fake, or a recorded reply.

### 1.3 The status machine

```
POST /advisor/sessions ─ pre-check ─┬─ refused (question.*)        ┐ finished at once,
                                    ├─ unanswerable (out_of_scope) ┘ no model, no job
                                    └─ clarifying ─ [clarify call] ─┬─ refused (clarify.*) / failed / cancelled
                                                                    └─ clarifying (clarification set): the holder answers
POST …/answers ─ pre-check each ────┬─ refused (answer.*), no model
                                    └─ gathering ─ [gather call] ─ the calls ─┬─ refused (gather.*) / unanswerable
                                         └─ options ─ [options call] ─┬─ refused (options.*)
                                              └─ tradeoffs ─ [tradeoffs call] ─┬─ refused (tradeoffs.*)
                                                   └─ [judge call: score or judge_error, never a stop] ─ awaiting_pick
POST …/pick ─ planning ─ [plan call] ─┬─ refused (plan.*) / failed (watcher_unavailable)
                                      └─ tracked ─ the watcher (no model): once now, then daily
any open status ─ POST …/cancel ─ cancelled (holder_cancelled; a step in flight asked to stop)
any step ─ gate refusal (approval withdrawn, a switch off) / spent budget / a stale claim ─ failed (by name)
```

## 5. Migration

`0061_advisor_sessions.sql`, expand-only, references `users` and its own `advisor_sessions`; CHECKs in the 0059/0060 style (each outcome whole or not at all; the protocol's order — no answers without a clarification, no gathered results without answers, no options without the context digest, no trade-offs without options, no pick without trade-offs, no plan without a pick; tracked exactly when plan, watcher and watcher id are set; the judge's score with its detail and run; finished exactly when final). Full text: `packages/db/migrations/0061_advisor_sessions.sql`. The load-bearing lines:

```sql
CREATE TABLE advisor_sessions (
  id UUID PRIMARY KEY, user_id UUID NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  question TEXT NOT NULL CHECK (char_length(question) BETWEEN 1 AND 500),
  status TEXT NOT NULL CHECK (status IN ('clarifying','gathering','options','tradeoffs','awaiting_pick',
                                         'planning','tracked','refused','unanswerable','failed','cancelled')),
  catalogue_version TEXT NOT NULL, clarification JSONB, answers JSONB /* ≤ 2 */, gathered JSONB,
  context_digest TEXT /* sha256 */, options JSONB /* 2..4 */, tradeoffs JSONB /* 2..4 */,
  picked_option TEXT /* o1..o4 */, plan JSONB /* 1..6 */, watcher_id UUID, watcher JSONB,
  judge_score NUMERIC(4,3) /* 0..1 */, judge_run_id UUID, judge_detail JSONB, judge_error TEXT,
  refusal TEXT /* (question|answer|clarify|gather|options|tradeoffs|plan).* */,
  unanswerable_reason TEXT, unanswerable_topic TEXT, nearest_screen TEXT, error_code TEXT,
  token_budget INTEGER NOT NULL CHECK (token_budget BETWEEN 1000 AND 1000000),
  tokens_used INTEGER NOT NULL DEFAULT 0, hosted_window_left INTEGER,
  created_at, updated_at, finished_at TIMESTAMPTZ,
  UNIQUE (user_id, id), … 14 whole/order CHECKs …
);
CREATE TABLE advisor_session_steps (
  id UUID PRIMARY KEY, user_id UUID NOT NULL REFERENCES users (id) ON DELETE CASCADE, session_id UUID NOT NULL,
  step TEXT NOT NULL CHECK (step IN ('clarify','gather','options','tradeoffs','plan','judge')),
  run_id UUID NOT NULL, input_digest TEXT NOT NULL /* sha256 */, llm_provider TEXT NOT NULL, llm_model TEXT NOT NULL,
  egress TEXT NOT NULL CHECK (egress IN ('local','hosted')), outcome TEXT, refusal TEXT, error_code TEXT,
  knowledge_read JSONB, tokens INTEGER, duration_ms INTEGER, created_at, finished_at,
  FOREIGN KEY (user_id, session_id) REFERENCES advisor_sessions (user_id, id) ON DELETE CASCADE,
  CONSTRAINT advisor_session_steps_one_per_step UNIQUE (session_id, step), …
);
CREATE TABLE advisor_settings (
  user_id UUID PRIMARY KEY REFERENCES users (id) ON DELETE CASCADE,
  hosted_provider TEXT CHECK (hosted_provider IN ('openai','openrouter','anthropic')),
  hosted_consented_at TIMESTAMPTZ, hosted_consent_text_hash TEXT /* sha256 */, updated_at,
  CHECK ((hosted_consented_at IS NULL) = (hosted_consent_text_hash IS NULL))
);
```
