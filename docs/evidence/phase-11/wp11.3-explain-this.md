# WP 11.3: "Explain this" — grounded explanations on insights and health pillars

**Request (Chris, verbatim).** 2026-10-19: "i think i need more LLM integration for the Insights Advisor …". 2026-10-25: "Good with the llm proposal". 2026-10-26: "Good with proposal. Use a hosted model, I agree a locally hosted low parameter won't be strong enough" (D31 — that decision covers the advisor query types of docs/research/12; for Explain-this the narrator's existing provider choice and consent apply, because the payload class is the same minimised one the narrator already receives). WP 11.3 is package 11.3 of `docs/research/11-llm-integration-design-proposal.md` §5 (§3.2's Explain-this row, §4's `insight.explain`).

**Result.** (1) **`insight.explain`**, a third `local_model` query type beside the narrator and `categorize.suggest`: its own manifest (scopes bounded by the narrator's list, never `transactions.raw`; each request carries exactly its entity's own scopes, and is sent only when every one is in the holder's live narrator grant), its own approval shape (`queryShape` over advisor id, version, kind, scopes, template hash) approved once in **Advisor management** through the same preview/approval routes as the narrator, the narrator's kill ladder (level 2 is the `local_model` kind switch and the holder's narrator — Off is off), an `advisor_runs` row per explanation with the payload digest and the payload retained, and a validator with eight named refusal classes (`schema`, `empty`, `too_long`, `markup`, `link`, `numeral`, `word_figure`, `copy`). The numerals check is the narrator's narrow trace over **this subject's evidence values and own figures only**. (2) The same query type for **health pillars** (`entity_kind: 'health_pillar'`): the pillar's ladder in words, its "Built from" inputs with values, its band and the next band's edge. (3) **The cache** `insight_explanations` (migration `0057`), one row per (holder, entity, evidence digest): reused, a new digest a new row, the old kept, nothing deleted on dismissal; a refusal cached as its class. (4) **Routes** `POST|GET /insights/{id}/explain` and `POST|GET /insights/health/{pillar}/explain`: 200 with the explanation/refusal/unavailable reason, else 202 `computing` with an `insights.explain` job for the worker — the api has no path to a model. (5) The **Brief prefetches** its ranked items, at most five, each only if explainable now and not cached. (6) **Provider**: the narrator's own, through `createNarratorRuntime`'s per-holder `resolve` — local Ollama by default, a hosted provider only when it is the narrator under WP 10.6's consent, with the narrator's key and hourly window; no new consent. (7) The 10.16 self-test gains a thirteenth check, **`explain_grounding`**. (8) The web: "Explain this" on `InsightCard` and on every scored pillar card and detail (§1.8). **No live model was called**: every model in this package's tests is the Ollama fake or the vendor fake; Chris's first Explain is the live check.

**State of the tree.** Uncommitted, on `main` after `78e087b`. Nothing staged by this WP. One migration, expand-only: `0057_insight_explanations.sql` (§5). The narrator's own files are byte-identical to HEAD: `git diff --quiet HEAD -- packages/contexts/insights/src/{preview.ts,validate/,snapshot/,advisors/local/}` exits 0.

**Not done by design.**

- **A finding built from raw transaction rows cannot be explained.** Its source run emitted `transactions.raw`, which the narrator's bound never contains, so the scope check refuses it (`scope_not_granted`, nothing sent, no run). That is the duplicate-service, uncategorised and duplicate-charge rules — the same findings the narrator never narrates.
- **A pillar's scopes are its snapshot blocks** (`PILLAR_SCOPES`: e.g. emergency fund = `cash.summary` + `cashflow.monthly`) and are held to the narrator grant like an insight's. The brief said "no new scope"; none is added — but a pillar is not explained to a hosted provider the holder never let read those blocks.
- **The cache is keyed by the evidence digest, not the provider.** An explanation given by the local model is reused after the holder switches the narrator to a hosted provider (and vice versa) until the evidence changes; its badge names the provider that wrote it.
- **A cached explanation is shown only while explanations are available** (narrator on, the shape approved, scopes granted); Off hides it behind "unavailable" rather than showing model text the holder has since switched off.
- **`insight.explain` is registered on** (`advisors.enabled` true by default): nothing runs without the holder's tap or the Brief's prefetch and an approved shape, and level 3's switch in Advisor management still turns it off.
- **On a pillar card the explanation opens under the card's footer**, below the "Built from" inputs it was worded from ("Worded from the inputs above"): the button sits beside "See detail" on the baseline every card in a row shares, because a button above the inputs made Tab jump up the 3-up grid (the keyboard walk's WCAG 2.4.3 check failed on `/health` and passes now). On the pillar detail and on every insight card the evidence stays beneath the explanation.
- **The Brief shows no button**: it does not render `InsightCard`; its ranked items are prefetched, so their explanation is already there when the holder opens the insight.
- **`just genai-selftest` (the CLI) binds no explain model**, so `explain_grounding` reads "not applicable" there; the worker's self-test (Settings) binds it.
- **`~/personalfi-prod`, project `personalfi-prod`, its volumes, images and secrets** were not read, listed, built or touched. No compose service was started; the `ollama` container and its volume were not touched.

## 1. What was built

### 1.1 The payload (scope minimisation), pinned by `packages/contexts/insights/test/wp113-explain.test.ts`

**An insight.** Built from the narrator's `FindingSource` through the narrator's own `redactFreeText` and `narratedFindingOf(…, 'quoted')` (every value as the evidence panel shows it), then an explicit field list (`insightSubjectOf`, re-listed again by `buildExplainRequest`). The test hands it a subject carrying an insight id and an account name and a goal-name evidence row "Pay off Visa 4532"; the retained, digested, sent payload is:

```json
{
  "granted_scopes": ["cash.summary", "cashflow.monthly", "goals.list"],
  "snapshot": {
    "explain": {
      "entity_kind": "insight",
      "evidence": [
        {
          "label": "Cash in checking and savings",
          "source_ref": "snapshot:cash_summary.total.minor",
          "value": "$7,200.00"
        },
        {
          "label": "Average monthly spending",
          "source_ref": "snapshot:cashflow_monthly.average_expense.minor",
          "value": "$3,000.00"
        },
        {
          "label": "Goal",
          "source_ref": "snapshot:goals_list.goals[0].name",
          "value": "Pay off Visa"
        }
      ],
      "figures": {
        "basis": "Months of spending the cash would cover.",
        "one_time": null,
        "per_year": null
      },
      "rule": {
        "name": "Emergency fund",
        "text": "Reports how many months of recent spending the cash on hand would cover."
      },
      "summary": "Cash of $7,200.00 covers 2.4 months of your recent spending of $3,000.00 a month.",
      "title": "Your cash covers 2.4 months of spending"
    }
  }
}
```

No id, no account name, no `4532`; a minor-unit evidence leaf (`300000` under `.minor`) arrives as `$3,000.00`; `granted_scopes` is the insight's own source run's `emitted_scopes`, never the manifest's thirteen.

**A pillar** (`pillarSubjectOf`, a scored emergency-fund pillar with two money inputs and a count):

```json
{
  "granted_scopes": ["cash.summary", "cashflow.monthly"],
  "snapshot": {
    "explain": {
      "band": "Fair",
      "built_from": [
        { "label": "Cash in checking and savings", "value": "$7,200.00" },
        { "label": "Cash accounts", "value": "2" },
        { "label": "Average monthly spending (last 6 months with spending)", "value": "$3,000.00" }
      ],
      "entity_kind": "health_pillar",
      "ladder": [
        "Poor: under 1 month",
        "Fair: 1 month to under 3 months",
        "Good: 3 months to under 6 months",
        "Excellent: 6 months or more"
      ],
      "next_band": { "band": "Good", "edge": "3 months" },
      "pillar": {
        "meaning": "How many months your cash would cover your spending.",
        "name": "Emergency fund"
      },
      "score": "50 out of 100",
      "value": "2.4 months"
    }
  }
}
```

The pillar inputs' labels are `pillars.ts`'s fixed strings: no account or institution name can appear. A withheld pillar is not explained (`pillar_not_scored`).

### 1.2 `insight.explain` (`packages/contexts/insights/src/advisors/explain/`)

- **`manifest.ts`** — `insight.explain` 1.0.0, kind `local_model`, `requires_scopes` = `NARRATOR_SCOPES` (the bound), narrates-only, no impact, info at most, no triggers, 300 s, 16 KiB reply cap, no egress. `EXPLAIN_PREFETCH_MAX = 5`. Registered as an `advisors` row (on) by `registerBuiltinAdvisors`; not in the nightly registry.
- **`request.ts`** — `insightSubjectOf`, `pillarSubjectOf` (ladder words and next-band edge from `HEALTH_BAND_THRESHOLDS`, the same words `/health/:pillar` prints), `buildExplainRequest` (payload `{snapshot:{explain}, granted_scopes}`, `digest = canonicalRunDigest(payload)` — the cache key and `advisor_runs.input_digest`), `explainTraceContext` (the narrow trace: figures = the evidence values and the entity's own figures as written; the rule text, title, summary, basis, a pillar's meaning and ladder lines may be quoted whole, never mined for a figure).
- **`reply.ts`** — `validateExplainReply`: schema pin `{explanation}` exactly; 1–900 characters; the narrator's Markdown subset and no braces/angle brackets (a slot `{{e1}}` is refused); no link, Markdown or bare; `untraceableInFinding` and `untraceableWordFiguresInFinding` over the subject's trace; the insight copy linter (`lintAdviceCopy`: banned phrases, a sentence-opening imperative, a merchant pseudonym).
- **`run.ts`** — `runInsightExplain`: (0) the cache by digest — a hit sends nothing; (1) the scope bound (`ungrantedExplainScopes`: the entity's scopes ⊆ the narrator's effective grant ∩ the bound) — otherwise nothing sent and no run; (2) the gate through `decideContinue` (level 1, level 2 = kind switch ∧ a model bound for this holder, level 3 = the row and its quarantine, the approval for the shape); (3) the run row, prompt hash, model, retained payload; (4) the call watched (switches and cancel once a second, the deadline); (5) the barrier; (6) validation and the cache write in the run's finishing transaction — text or refusal class; a failed call writes no cache row. The breaker counts a call failure or a reply outside the format, never a content refusal. `explainUnavailable` is the same gate for the route, the job and the prefetch.
- **`preview.ts`** — `ensureInsightExplainAdvisor` (insert-only on the run path), `previewInsightExplain` (the holder's top explainable insight, else a fixed illustrative subject, labelled), `approveInsightExplain` (writes `advisor_payload_approvals` with provider and model, refusing `shape_changed`).
- **`source.ts`** — `loadInsightExplainTarget` (a built-in's own finding with evidence and its source run on record — fail closed otherwise), `loadPillarExplainTarget` (the latest stored daily health snapshot), the cache (`findExplanation`, `listExplanations`, `recordExplanation` — on conflict do nothing: computed once per digest, never overwritten), `latestExplainRun`.
- **`jobs.ts`** — `insights.explain`, deduped per (holder, entity, digest), `maxAttempts: 1`, priority 10 for a tap and 500 for the prefetch; `briefPrefetchIds` (ranked items, rank order, at most five).

### 1.3 The model call (`@advisor/local-model` `src/explain.ts`, by the adapter sub-agent)

`renderExplainPrompt` (a constant system region; every string of the subject through `sanitiseTree`; one `<untrusted_data>` fence holding `canonicalJson({subject})`; `<`/`>` escaped; caps 32 evidence rows / 16 inputs / 8 ladder steps), `EXPLAIN_FORMAT` (`{explanation: string}`, no keyword a hosted strict mode strips), `EXPLAIN_PROMPT_TEMPLATE_HASH`, `createLocalExplainAdapter` (the narrator's endpoint policy, digest pin before and after, warm-up only in headroom, timeout = min(`LOCAL_MODEL_TIMEOUT_MS`, deadline), byte cap, abort counter, counts-only logging), `createHostedExplainAdapter` (`createHostedCaller`: one host, the key, redaction, error mapping; **the narrator's hourly budget passed through**), `controlProbe('explain_grounding')` asking for `$9,173.46`. The system prompt asks for one plain paragraph on why it appeared, what it is built from and what would change it (for a pillar: what moves it to the next band), figures only copied exactly from the data, no advice, no links, no Markdown. 67 tests in `test/explain.test.ts`.

### 1.4 The composition (`apps/api/src/insight-explain.ts`)

- `createExplainRuntime` resolves through the narrator runtime's `resolve(userId)`: Off/unconfigured → no adapter; the local model with the narrator's pin (environment over Settings; in the api, the pin from the narrator's label) and the narrator's stored bearer; a hosted provider only when the narrator resolution is non-null — which already required its standing consent and a key — with the narrator's model and `budgets.get(provider)`. Preview mode (the api) builds rejecting transports.
- `createExplainJob` (`insights.explain`, worker only, concurrency 1), `runExplainPass`, `createExplainPrefetch` (caps at five a second time; skips the unexplainable, the unavailable and the cached), `explainProbeFor`.
- Wiring: `worker.ts` builds the run-mode runtime and passes `insightExplain` to `appModules` (the job, the Brief's `explainPrefetch`, the self-test's `explainProbeFor`); `app.ts` builds the preview-mode runtime for the routes and Advisor management.

### 1.5 Routes (OpenAPI and the web SDK regenerated)

`POST /insights/{insightId}/explain`, `GET /insights/{insightId}/explain`, `POST /insights/health/{pillar}/explain`, `GET /insights/health/{pillar}/explain` — session; response `InsightExplanationState {state: idle|computing|shown|refused|unavailable|failed, entityKind, entityId, explanation {text, provider, providerName, model, createdAt, runId} | null, refusal, reason, message}`. `GET /advisors/insight.explain/payload-preview` and `POST /advisors/insight.explain/payload-approvals` (step-up) serve the explain shape; the preview's `request` is now `AdvisorRequest | ExplainPreviewRequest`. Nothing on these routes writes an approval (other than the explicit approve), a grant, a consent or a setting.

### 1.6 The Brief

`createBriefJob` gains an optional `explainPrefetch`, called after the narration enqueues with `briefPrefetchIds(assembled.ranked…)`, never awaited by anything the Brief depends on; a failure is logged and the Brief stands.

### 1.7 The self-test

`explain_grounding` (worker, thirteenth): the explain adapter's control probe over a synthetic subject (`EXPLAIN_PROBE_TARGET`, `$250.00`) asked for `$9,173.46`; pass when the validator refuses (or the model declines), fail if a reply carrying the figure is accepted; not applicable with no explain model.

### 1.8 The web (by the web sub-agent; one layout fix by me)

- `features/insights/useExplanation.ts` — GET on mount only (a cached or Brief-prefetched explanation shows without a tap; `computing` resumes polling), POST on the tap, poll every 1.5 s while `computing`, stop on any other state, give up after 3 minutes with "taking longer than usual" and Try again; a failed POST reads as `failed`.
- `features/insights/ExplainThis.tsx` — `ExplainButton` ("Explain this", `aria-disabled`+`aria-busy` while computing, a permanent polite `role="status"` region saying "Explaining…", a `motion-safe:` spinner; focus moves to the outcome after a tap) and `ExplanationResult`: **shown** = the text as plain text (no Markdown at all), a Bot-icon accent badge "Explained by the local model <name@sha256:…>" / "Explained by <Provider> <model>" and a visible "AI-assisted wording" label; **refused** = the api's words, visibly, never template wording; **unavailable** = the message, a link to Advisor management (and Settings for Off/not configured), no retry; **failed** = the message and Try again.
- `InsightCard`: the button beside the evidence toggle; once an explanation is shown or refused the evidence panel is forced open beneath it. `EvidencePanel`'s source line now wraps instead of truncating (the new 200 %-zoom + text-spacing test failed on it, WCAG 1.4.12).
- Health: scored pillar cards (footer, §"Not done") and `/health/:pillar` (under the figure, above "What it is built from"); withheld pillars none.
- The thirteenth self-test check in the narrator settings fixtures, words and counts.

## 5. Migration

`0057_insight_explanations.sql` (expand-only; references only `users`):

```sql
CREATE TABLE insight_explanations (
  id                UUID         PRIMARY KEY,
  user_id           UUID         NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  entity_kind       TEXT         NOT NULL
                                 CONSTRAINT insight_explanations_entity_kind_check
                                 CHECK (entity_kind IN ('insight', 'health_pillar')),
  entity_id         TEXT         NOT NULL
                                 CONSTRAINT insight_explanations_entity_id_check
                                 CHECK (char_length(entity_id) BETWEEN 1 AND 64),
  evidence_digest   TEXT         NOT NULL
                                 CONSTRAINT insight_explanations_digest_check
                                 CHECK (evidence_digest ~ '^sha256:[0-9a-f]{64}$'),
  explanation_text  TEXT         CONSTRAINT insight_explanations_text_check
                                 CHECK (explanation_text IS NULL OR char_length(explanation_text) BETWEEN 1 AND 900),
  refusal           TEXT         CONSTRAINT insight_explanations_refusal_check
                                 CHECK (refusal IS NULL OR refusal ~ '^[a-z][a-z_]{0,47}$'),
  llm_provider      TEXT         NOT NULL
                                 CONSTRAINT insight_explanations_provider_check
                                 CHECK (llm_provider IN ('ollama', 'openai', 'openrouter', 'anthropic')),
  llm_model         TEXT         NOT NULL
                                 CONSTRAINT insight_explanations_model_check
                                 CHECK (char_length(llm_model) BETWEEN 1 AND 200),
  run_id            UUID         NOT NULL,
  created_at        TIMESTAMPTZ  NOT NULL DEFAULT now(),

  CONSTRAINT insight_explanations_text_or_refusal
    CHECK ((explanation_text IS NULL) <> (refusal IS NULL))
);

CREATE UNIQUE INDEX insight_explanations_digest_idx
  ON insight_explanations (user_id, entity_kind, entity_id, evidence_digest);

CREATE INDEX insight_explanations_entity_idx
  ON insight_explanations (user_id, entity_kind, entity_id, created_at DESC);
```

plus three `COMMENT ON`s.
