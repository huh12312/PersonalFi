**Result.**

1. **The parameter store is WP 4.2's, unchanged, and now citable by key.** Row 11.5a asks for `config/tax/us_2026.yaml` and `config/assumptions.yaml`. Those already exist as WP 4.2's checked-in, cited, hashed TypeScript data modules (`packages/contexts/planning/data/`), and the repo deliberately has no YAML loader. No YAML was added and no `config/` was created.
   - Every Appendix A and §5.5 row is already a cited node (§2 below), so **nothing was added**, and `assumptionsVersion()` did not move: `sha256:4997f2ff8bd4381f8e5a3e675ac3ea173d0e9d8a85d66b4319ee7472ea3b42be` before and after.
   - New: `packages/contexts/planning/src/parameters.ts` gives each of the file's **93 cited nodes** a stable key, for example `tax.us.2026.retirement.elective_deferral` or `assumptions.withdrawal_policy.guardrail_reference_rate`. `parameterByKey(key)` resolves a key to `{ kind, value, source, asOf, …, parametersVersion }` as wire data: `Money` as `{ minor, currency }` strings, never a `bigint` or a float.
   - A `tax.us.2027.…` key throws the existing `AssumptionsYearUnavailable`, naming the years held. There is no fallback year.
2. **The playbook: eight pages, all `status: draft`.** They are in `docs/advisor/playbook/`, in the order the dispatch gave. Each has frontmatter (key, title, version 1, status, primary sources) and exactly the four sections. The 20 limits the pages state are `{{param:…}}` placeholders, rendered from the store when a page is read. Every other number sits in a sentence with a `[^id]` source marker. The README explains the format, the review gate and the version bump.
3. **The generator and the drift check.** `scripts/playbook-gen.ts` (`pnpm run playbook`, `just playbook`) is the only reader of the markdown. It emits `packages/contexts/insights/data/playbook.ts`: each parsed page's key, title, version, status, reviewer, sources, sections, parameter keys and `digest`. `--check` (`just playbook-check`, plus a new step in CI's **lint** job, commented) fails on drift and on any page that breaks the format.
4. **The review gate, in code, twice.**
   - The generator refuses `status: reviewed` without `reviewed_by`, `reviewed_on` and a `reviewed_digest` equal to the body's digest. A page edited after review therefore cannot stay `reviewed`.
   - The runtime knowledge base refuses any page that is not `reviewed` with both fields set (`playbook.unreviewed`). It also re-takes the digest and refuses a mismatch (`playbook.digest_mismatch`).
   - Nothing in this package marks a page reviewed.
5. **The citation resolver.**
   - `packages/contexts/insights/src/knowledge/` holds `createKnowledgeBase({ params })`, with `playbook.get(key)` and `params.get(key)`. Planning's store reaches it through a `ParameterPort` bound at the composition root, `apps/api/src/knowledge-base.ts`, because `@ctx/insights` may not import `@ctx/planning`.
   - It also holds `resolveCitations(text, { pages, params, allowedFigures }, catalogue)`. Narration markers are `[playbook:<key>]` and `[param:<key>]`.
   - Six refusal classes: `citation.malformed`, `citation.unknown`, `citation.page_not_sent`, `citation.param_not_sent`, `numeral` and `word_figure`. The figure checks reuse `validate/numerals.ts`'s narrow, as-written trace.
   - The record a narration keeps is `KnowledgeReadRecord` (`knowledgeReadRecordSchema`, format `personalfi.knowledge-read/1`): every page sent by key, version and digest; every parameter sent by key, kind, rendered value, as-of and store version; and the keys actually cited. 11.5d stores it.
6. **The inlined-limits sweep found no tax or contribution figure typed into code** (§3). Nothing was switched.
7. **Docs**: RUNBOOK "The advisor's knowledge base (v0.9.21)", release notes `## v0.9.21`, a pointer in 12 §6's row 11.5a, and a non-table note in `packages/contexts/insights/OWNERSHIP.md`.

## 7. For the orchestrator, and choices Chris should know about

- **(a) No YAML; the store was already complete.** Appendix A and §5.5 are fully held, so `assumptionsVersion()` did not move. No retained predecessor was needed, and the migration test and soak canary are unaffected. The parameter "YAML" of row 11.5a is the WP 4.2 module, now addressable by key.
- **(b) EF target months is not in the store, and C4 still holds `EMERGENCY_FUND_TARGET_MONTHS = 3`.**
  - 12 §2.2 lists "EF target months" among the assumptions-store contents, but it is not an Appendix A or §5.5 row.
  - Adding it moves `assumptionsVersion()`. That means a retained predecessor, and every stored projection run would read stale.
  - It would still not be read by the rule: insights cannot import planning, and the snapshot carries no target. That would need a snapshot-contract change.
  - The emergency-fund page therefore states no app target: it cites the Fed's three-month yardstick with a marker. **Chris's call** whether to move the target into the store, which would also make it overridable.
- **(c) `reviewed_digest`.** The dispatch's gate is `reviewed_by` + `reviewed_on`. I added a third required field, the digest of the body that was reviewed, because without it an edit to a reviewed page would keep its `reviewed` status and reach a model unreviewed. The generator prints the digest (`--digest`) and the exact line to paste. The RUNBOOK and README say so.
- **(d) A tax-year placeholder renders with its year**, for example `$7,500 (tax year 2026)`, so a page read after the year rolls still says which year's limit it states. Moving a page to 2027 is an edit plus a version bump, once the store holds 2027.
- **(e) Narration citation syntax** is `[playbook:<key>]` / `[param:<key>]`, chosen here because 11.5c–d will need one. A parameter rendered into a sent page counts as sent. A figure that appears on a sent page is allowed (12 §4, "the union of catalogue results and quoted knowledge pages"); a figure derived from one is not.
- **(f) The digest** is `sha256:` + SHA-256 over the canonical JSON of `{ body }`, through `@core/platform`'s `configHash`, rather than over the raw bytes. The generator and the runtime share one function, and the runtime re-checks it.
- **(g) Sources.** See §4 for which were fetched and which are printed citations checked against the repo. The two journal articles are the ones to look at hardest during review.
- **Nothing to commit specially.** Commit `packages/contexts/insights/data/playbook.ts` with the pages; CI's new lint step checks they agree.
