# WP 10.6: The language model in Settings — local, or bring your own key

**Request (Chris, verbatim):** "i want to make the LLM setup available in the setting as well. ideally options include ollama/openai/openrouter/anthropic options where you can bring your own api key for use."

**Result.** Settings has a **Language model** tab: the active provider (Ollama / OpenAI / OpenRouter / Anthropic / Off), and a card per provider with where its key comes from (the operator's file, stored here with its last four characters, or not set), a masked key field (**Save with passkey**, **Remove**), the model id (defaults `claude-sonnet-5-5`, `gpt-6.1-sol`, `anthropic/claude-sonnet-5.5`; Ollama's pinned name and digest read-only when the environment pins them, else an endpoint/name/digest validated by the existing local-endpoint policy), a **Test** button (a fixed probe with no personal data; the round trip in words), and for each hosted provider a **consent checkbox** whose text says what leaves the machine (_Brief findings: aggregated amounts, bucketed, merchants pseudonymised — never a transaction, never an account number_), recorded with its version and the sha256 of the exact text. A hosted provider cannot be made active without its consent and a key; making one active (or changing its model) revokes the narrator's payload approvals, and a new approval records the provider and model it was given for. The narrator on a hosted provider gets exactly the minimised, previewed, approved payload the local model gets, through the same `renderPrompt`, and its reply through the same wrap (`reply.ts`, now shared) and the same `validateResponse` — reply format, 1:1 match, numerals check. Each adapter reaches exactly one host (`api.openai.com`, `openrouter.ai`, `api.anthropic.com`), checked in code; the local model's 300 s timeout ceiling, the run's `AbortSignal` on the socket, an hourly budget window per provider, provider strings redacted before logging. Keys are sealed under the KEK in `provider_credentials` (widened), never returned, logged or exported; a non-empty operator file wins. The worker resolves the holder's narrator per run (30 s cache, generation counter, dropped by `insights.NarratorSettingsChanged` and `connections.ProviderCredentialsChanged`) — no restart. Off (or a withdrawn consent) stops it: kill level 2 refuses a queued narration `kind_disabled`, by name, and the Brief enqueues none. The Brief's narration badge names the provider and model. Decision **D30** (revising D22) records it as Chris's request.

**State of the tree.** Uncommitted, on `main` (dispatched at `e5dbed9`; the orchestrator's own `2fa6e55`, an execution-log commit, landed while this WP ran — HEAD is now `2fa6e55`). Nothing staged by this WP (`docs/plan/01-execution-log.md` was already staged before it started and is not this WP's).

**Not done by this WP, by design.** No live call to OpenAI, OpenRouter or Anthropic: every adapter test runs over a hermetic fake transport (`@advisor/local-model/test`'s `FakeHostedTransport` / `RejectingHostedTransport`) that answers in each vendor's documented reply shape, refuses like a vendor (401, 429, 400, 503, 307, a declined answer, an off-shape body), or never answers. **Chris's first Test press is the live check** — in particular whether each vendor compiles the derived reply format (see §4). A key is not validated on Save (the Test button is the check; WP 10.4 validated on save because a market-data key has a free cheap call, a hosted model call costs money). No new compose network: the worker and the api already have outbound HTTPS on `backend`. `scripts/advisor-eval.ts --live` still measures the local model only (it goes through `createNarratorWiring`, unchanged); a counted hosted eval would be a live call. `~/personalfi-prod`, project `personalfi-prod`, its volumes, images and secrets were not read or touched; the `ollama` container and `personalfi_ollama_models` were not touched; no compose db was brought up.

## 4. The vendor reply formats (what each vendor documents, read 2026-10-15)

`NARRATION_FORMAT` uses `maxLength` on strings, `maxItems` on arrays (5 for insights, 0 for derivations / proposed actions / caveats), number and integer `enum`s, `type: null`, `additionalProperties: false`, every property required.

- **Anthropic** (`claude-api` skill; platform.claude.com structured-outputs page): `output_config.format: {type: 'json_schema', schema}`; supported: all basic types incl. `null`, `enum` of numbers, `additionalProperties: false`, `minItems` 0/1; **not** supported: `minLength`/`maxLength`, any other array constraint (`maxItems`). Reply in a `text` block. → `maxLength` and `maxItems` removed.
- **OpenAI** (developers.openai.com structured-outputs, "Supported schemas"): `response_format: {type: 'json_schema', json_schema: {name, strict: true, schema}}`; all fields required, `additionalProperties: false`; string `pattern`/`format` supported, `maxLength` not listed; array `minItems`/`maxItems` supported. → `maxLength` removed. Default model `gpt-6.1-sol` (models page: balances performance and cost; Chat Completions and structured outputs supported; no temperature/seed — none are sent).
- **OpenRouter** (openrouter.ai API reference and structured-outputs guide): OpenAI's shape at `https://openrouter.ai/api/v1/chat/completions`, `Authorization: Bearer`, attribution `HTTP-Referer` and `X-OpenRouter-Title`; `provider.require_parameters: true` so it routes only to endpoints that honour `response_format`. → OpenAI's derivation. Default slug `anthropic/claude-sonnet-5.5` (listed on openrouter.ai/anthropic).
- An empty-by-contract array (`maxItems: 0`, no `items`) gains `items: {type: 'null'}` for all three (no vendor documents an `items`-less array); the validator refuses anything in it regardless.

**The risk the first Test press settles:** whether OpenAI's strict mode compiles `type: 'null'` leaves and number `enum`s as written. If it does not, the Test answers "refused the request (HTTP 400)" in words and nothing is narrated; the remedy is one more keyword in `STRIPPED_KEYWORDS` (the derivation test pins the list).
