# OWASP ASVS 5.0 assessment — PersonalFi at `beaa8be` (v0.9 candidate)

**What this is.** The self-assessment 03 §9 P2-8 names, and WP 9.10's first deliverable (`docs/plan/09-phase-9-dispatch.md` §3 "WP 9.10").
**Scope.** Every ASVS 5.0.0 requirement at **L1 and L2** across all seventeen chapters, plus **L3** for V6 Authentication, V7 Session Management, V11 Cryptography and V13.3 Secret Management: 278 rows. The source is the OWASP CSV `OWASP_Application_Security_Verification_Standard_5.0.0_en.csv` at tag `v5.0.0`, sha256 `98c8fe91…f680`, copied to `/tmp/wp910/asvs/asvs.csv`.
**Who.** An external-style reviewer (Opus security-engineer) that wrote none of the reviewed code. **It reviews and records; it never fixes.** Every gap goes to WP 9.11, or to Chris as an accepted risk.
**Against what.** HEAD `beaa8be` (Wave B, CI green). The stack under review is `pf-review`, built from `git archive beaa8be` and run through Caddy on `127.0.0.1:8471`.
**Companion files.** `docs/security/threat-model.md` re-walks the STRIDE register and re-rates 03 §9. `docs/evidence/phase-9/wp9.10-security-review.md` holds the log, every sabotage this review ran (§2), the ZAP baseline (§3) and **the gap list** (§5). A `G-xx` cited below is defined there.

## Method and the meaning of each status

The bar comes from the gate lessons: **a control nobody has watched fail is not evidence.** Each row's status means exactly one of these:

| Status                       | Meaning                                                                                                                                                                                                                                                                    |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **met**                      | The control exists, **and** a test in the tree was observed going red with the control removed. The row cites that observation: a phase gate's §2 sabotage, a WP's sabotage log, or this review's own `SAB-xx` (wp9.10 §2: file, edit, test, red, restored byte-for-byte). |
| **met (doc)**                | A documentation-only requirement ("verify that the documentation defines …"). No executable control exists to sabotage. The evidence is the named document, and the gate may test its accuracy.                                                                            |
| **gap → G-xx**               | Not met, or met in the code but never observed failing, so a regression would pass CI. The gap list carries the severity, the fix and the owner.                                                                                                                           |
| **accepted risk (proposed)** | A deliberate design decision, or a platform/host property this repository does not control. The residual risk is stated. It is accepted only when Chris signs in writing (09 §5 item 9); until then it reads as proposed.                                                  |
| **N/A**                      | The technology or feature the requirement governs does not exist in this system, and the reason is given.                                                                                                                                                                  |

Shorthand used in the evidence column:

- `P0G` … `P5G` are `docs/evidence/phase-N/gate-security-review.md`: Phase 0 §2–§3, Phase 1 §4 (S#) and §8.7 (G#), Phases 2–5 §2.
- `9.1 S3` and similar are a row in `docs/evidence/phase-9/wp9.N-*.md`'s sabotage log.
- `SAB-xx` is this review's own sabotage (wp9.10 §2).
- `ZAP` is wp9.10 §3, and `probe` is wp9.10 §1, an observation on the running `pf-review` stack. **A probe never makes a row "met"**: it shows that a control holds, not that a test would notice its absence.

Totals are in the last section.

## V11 Cryptography (L1, L2 and L3)

The inventory as built, read from the code at `beaa8be`:

- **Envelope.** XChaCha20-Poly1305 (`@noble/ciphers`), a mandatory AAD `personalfi/v1|table|column|row|key_version`, 24-byte random nonces, and a `version‖key_id‖nonce‖ct+tag` envelope. Keys are per-record or per-epoch DEKs wrapped by the KEK.
- **KEK.** Argon2id (`hash-wasm`) at m = 1 GiB, t = 4, p = 4 with a refused floor, from the `master_key` file secret.
- **Hashes.** SHA-256 (`@noble/hashes`) for token digests, export stream integrity and the migration checksum. Pseudonyms are keyed hashes of `advisor_token_secret`.
- **Lookup secrets.** Recovery codes are stored Argon2id-encoded.
- **Signatures.** WebAuthn ES256 and EdDSA (SimpleWebAuthn). The Coinbase CDP JWT is Ed25519 (`node:crypto` `KeyObject`).
- **Other.** TOTP is HMAC-SHA1 per RFC 6238 (otpauth). Backups and exports are `age` (X25519 + ChaCha20-Poly1305). Transport is TLS 1.2/1.3 by Caddy and Node.

The only crypto call site is `packages/secretbox/src/primitives.ts`, enforced by ESLint (**SAB-25**), with two forced carve-outs: the migration checksum and the CDP JWT.
